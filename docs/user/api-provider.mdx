# Provider Selection

- OpenRouter: wide range of model, native support(modality detection with openrouter API)
- OpenAI-Compatible: Functional, require more setup(need to specify modality)

## OpenRouter (Recommended)

**Setup:**

1. Sign up at [openrouter.ai](https://openrouter.ai)
2. Generate API key
3. Set in llumen:

```bash
export API_KEY="sk-or-v1-your-key"
# API_BASE defaults to OpenRouter
```

## OpenAI

**Setup:**

```bash
export API_KEY="sk-your-openai-key"
export API_BASE="https://api.openai.com"
```

## Other Providers

Any OpenAI-compatible API works:

```bash
export API_KEY="your-key"
export API_BASE="https://your-provider.com/v1"
```

**Tested Compatible services:**
- Gemini(official OpenAI-compatible proxy)
- Groq
- Ollama Cloud
- Naga.ac
- Copilot API
- OpenLLM

## OpenLLM

[OpenLLM](https://www.openllm.sh) serves your Claude, ChatGPT, Cursor, Kimi and Grok subscriptions, your provider API keys, and local models through one OpenAI-compatible API.

**Setup:**

1. Install OpenLLM and sign in: see the [OpenLLM quickstart](https://docs.openllm.sh/quickstart).
2. Set in llumen, using your OpenLLM API key:

```bash
export API_KEY="sk-llm-your-key"
export API_BASE="https://www.openllm.sh"
```

The hosted API reaches subscriptions through one of your machines running OpenLLM, so that machine must be online. To call the OpenLLM daemon on the same machine instead, use `API_BASE="http://127.0.0.1:8787"` (`http://host.docker.internal:8787` from Docker).

Leave `/v1` off `API_BASE`, because llumen adds it.

3. Add each model in Settings. Use a model id from `/v1/models`, or `ultra`, `plus` or `lite` to fall back to the next model when a provider is rate limited. Set `json = false` for these three, because OpenLLM doesn't enforce strict `json_schema` output on them:

```toml
display_name = "OpenLLM plus"
model_id = "plus"

[capability]
image = false
tool = true
json = false
```

llumen logs `Failed to fetch video models` at startup with OpenLLM. Chat is not affected.
